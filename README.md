# 이동형 도로 관제 (스냅샷 방식)

안드로이드 휴대폰을 도로 옆에 거치해 몇 초마다 사진을 올리고, 로그인한 직원이 웹에서 현재 도로 상황을 확인한다.
퇴근 시간대 2~3시간, 직원 최대 500명이 보는 것을 기준으로 설계했다. 요구사항은 [REQUIREMENTS.md](REQUIREMENTS.md) 참고.

## 화면
| 주소 | 누가 | 내용 |
|---|---|---|
| `/` | 직원 | 분할 화면, 클릭하면 크게 보기 + 디지털 줌, 공지·운영 시간 안내 |
| `/admin` | 관리자 | 카메라 · 운영 · 통계 · 계정 · 설정 탭, 이상 발생 시 상단 경고 막대 |
| `/cam` | 거치한 휴대폰 | 송출 화면 (관리자가 준 QR/링크로 접속, 앱 설치 없음) |

## 구조
```
[안드로이드 Chrome ×6] --HTTPS로 JPEG 업로드(N초마다)--> [Caddy: HTTPS] --> [FastAPI 서버 1개]
                                                                         ├─ 최신 사진·썸네일: 메모리
                                                                         ├─ 계정·카메라·설정·통계: SQLite
                                                                         └─ 15초마다: 이상 점검, 1분마다: 접속자 기록
[직원 브라우저 ×500] <-- 3초마다 목록 확인, 바뀐 사진만 받음 (분할 화면은 640px 썸네일) --
```

| 경로 | 역할 |
|---|---|
| `app/main.py` | 웹 서버 전체 (인증, 관제, 송출, 관리자 API, 백그라운드 점검) |
| `app/ops.py` | 운영 시간 계산, 카메라 이상 판정, 텔레그램 전송 (DB와 무관한 순수 로직) |
| `static/` | 화면 (빌드 도구 없이 HTML + JS) |
| `deploy/` | 우분투 설치 스크립트, systemd 서비스, Caddy 설정 |
| `loadtest/` | 시청자 500명 부하 시험 도구 |

## 로컬 실행
```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
처음 실행하면 콘솔에 초기 관리자 계정(`admin`)과 임시 비밀번호가 찍힌다. 첫 로그인 때 비밀번호를 바꿔야 한다.
휴대폰 카메라는 HTTPS에서만 켜지므로, 실폰 시험은 `cloudflared tunnel --url http://localhost:8000` 같은 임시 터널을 쓴다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `CCTV_DB` | `./cctv.db` | SQLite 파일 위치 |
| `CCTV_ADMIN_USER` / `CCTV_ADMIN_PASSWORD` | `admin` / 무작위 | 첫 실행 때 만들 관리자 계정 |
| `CCTV_SECURE_COOKIE` | `0` | HTTPS 운영 시 `1` |
| `CCTV_TELEGRAM_TOKEN` / `CCTV_TELEGRAM_CHAT_ID` | 없음 | 둘 다 있으면 텔레그램 알림 사용 |
| `CCTV_ALERT_GRACE` | `120` | 운영 시작 후 알림을 보내지 않는 시간(초). 휴대폰을 켜는 동안의 오탐 방지 |

## 운영 흐름
1. 관리자: `/admin` → **계정** 탭에서 사번 목록 붙여넣기 → 일괄 생성 (초기 비밀번호 = 사번)
2. 관리자: **카메라** 탭 → 카메라 추가 → 나온 QR을 거치할 휴대폰으로 찍기
3. 관리자: **운영** 탭 → 운영 시간(예: 평일 17:00~20:00) 저장, 필요하면 공지 게시
4. 휴대폰: Chrome에서 열린 송출 화면 → 충전기 연결 → "송출 시작"
   - 권장: Chrome 메뉴 → "홈 화면에 추가"로 설치, 안드로이드 "앱 고정"으로 화면 잠금
   - 운영 시간 밖에는 자동으로 대기하다가 시간이 되면 송출을 시작한다. 휴대폰은 켜 둔 채 두면 된다
5. 직원: `/` 접속 → 사번 로그인 → 첫 로그인 시 비밀번호 변경

## 클라우드 배포
네이버 클라우드 기준 단계별 안내는 [DEPLOY.md](DEPLOY.md). 설치는 `deploy/setup.sh` 한 번으로 끝난다 (Caddy가 HTTPS 자동 처리).
스냅샷은 서버 메모리에 두므로 반드시 **워커 1개**로 실행한다.

### 텔레그램 알림 켜기 (선택)
1. 텔레그램에서 `@BotFather` → `/newbot` → 봇 토큰을 받는다
2. 알림 받을 단체방에 봇을 초대하고 아무 메시지나 보낸 뒤, `https://api.telegram.org/bot<토큰>/getUpdates` 에서 `chat.id`를 확인한다
3. 서버의 `/etc/cctv.env`에 두 값을 넣고 `systemctl restart cctv`
4. 관리자 → 설정 탭에 "켜져 있습니다"가 나오면 끝

## 개발 내역

### 1차: MVP (2026-10-23)
- **스냅샷 방식 송출**: 휴대폰 Chrome이 N초마다 JPEG를 업로드. 동영상(WebRTC/HLS)보다 서버·비용·발열·LTE 안정성 면에서 유리하고, 정체 확인에는 충분
- **관제 화면**: 분할 화면 자동 갱신, 크게 보기 + 디지털 줌(휠·핀치·드래그·더블클릭), 경과 시간·오프라인 표시, 탭이 가려지거나 30분 무조작이면 갱신 중지
- **관리자**: 카메라 추가·수정·비활성화·키 재발급(QR), 사번 일괄 계정 생성, 차단(즉시 로그아웃)·비밀번호 초기화·관리자 지정
- **보안**: 비밀번호 PBKDF2 해시, 카메라 키 해시 저장, 로그인 5회 실패 시 5분 잠금, 첫 로그인 비밀번호 변경 강제(설정 가능), HttpOnly 세션 쿠키
- **송출 안정성**: 화면 꺼짐 방지(Wake Lock), 실패 시 재시도, 2분 연속 실패 시 페이지 자동 재시작, 키 폐기 시 즉시 중단

### 2차: 배포 준비 (2026-10-25)
- **카메라 원격 회전**: 관리자가 ↻ 버튼으로 90°씩 돌리면 휴대폰이 다음 사진부터 돌려서 올림
- **썸네일**: 서버가 640px 썸네일을 만들어 분할 화면에 사용, 크게 보기만 원본. 전송량 약 1/5~1/6
- **성능**: 자주 불리는 API를 비동기로 바꾸고, 카메라 목록 조회를 1초간 재사용
- **부하 시험 도구**: 가짜 카메라 6대 + 가상 시청자 500명. 로컬에서 오류 0건, 초당 약 730건 처리
- **연결 유지 시간 조정**: 업로드 주기(5초)와 서버 유휴 연결 종료(5초)가 겹쳐 생기던 업로드 오류를 keep-alive 75초로 해결
- **배포 스크립트**: `setup.sh`(설치·업데이트 겸용), systemd 서비스(재부팅 시 자동 시작, 권한 최소화), Caddy(HTTPS 자동)

### 3차: 운영 기능 (2026-10-25)
- **카메라 이상 알림**
  - 15초마다 점검: 신호 끊김(업로드 30초 이상 없음), 충전 끊김, 배터리 20% 미만
  - 관리자 화면 상단에 빨간 경고 막대 + 탭 제목에 `(⚠N)` + 알림음(새 이상이 생길 때만)
  - 텔레그램 설정 시 발생·해결을 메시지로 전송
  - 운영 시간 밖이나 운영 시작 직후 2분은 알리지 않음 (휴대폰을 켜는 동안 오탐 방지)
  - 충전 정보를 못 주는 기기는 "충전 끊김"으로 오인하지 않음
- **운영 시간**
  - 항상 운영 / 시간표(요일 + 시작·종료, 한국 시간) / 운영 중지 중 선택
  - 운영 시간 밖: 휴대폰은 사진을 찍지 않고 30초마다 상태만 확인 → 시간이 되면 자동 송출
  - 직원 화면은 지난 사진을 숨기고 "다음 운영: 내일 17:00~20:00" 안내
- **공지 배너**: 관리자가 게시하면 직원 화면 상단에 몇 초 안에 표시. 일반(📢)/주의(⚠) 두 종류, 200자 이내
- **접속 통계** (통계 탭)
  - 지금 보는 사람, 오늘 최고 동시 접속(시각), 오늘 접속한 사람(중복 제외)
  - 최근 24시간 동시 접속자 그래프 (서버가 꺼져 있던 구간은 선을 끊음, 마우스를 올리면 수치 표시)
  - 오늘 카메라별로 크게 본 사람 수, 최근 7일 요약
  - 1분마다 기록, 31일 지나면 자동 삭제
- **알림 기록**: 이상 발생·해결, 운영 시작·종료, 관리자의 운영 시간·공지 변경을 기록 (90일 보관)

### 4차: UI/UX 개선 (2026-10-25)
어두운 테마는 유지하고, 직원 대부분이 휴대폰으로 본다는 전제로 다듬었다. 전후 비교: `docs/ui-before-after.html`
- **관제 화면**: 휴대폰에서 6대가 한 화면에 들어오는 2열 보기(1열 전환 가능), 상단 버튼 → ☰ 메뉴, "실시간" 연결 표시,
  카메라별 갱신 상태 점(초록/노랑/빨강), 꺼진 카메라는 아래에 작게, "송출 중 4 / 6" 요약
- **크게 보기**: 닫기·제목·몇 번째만 남긴 상단, 옆으로 밀어 카메라 넘기기, 터치 기준 사용법 안내(3.5초 뒤 사라짐),
  휴대폰에서는 ＋/－ 버튼 숨김, 확대했을 때만 "원래 크기"
- **관리자**: 카메라 표에 최신 화면 썸네일, 버튼 5개 → 수정 + ⋯ 메뉴, 상태 칸 하나로 정리, 휴대폰에서는 카드 형태,
  브라우저 기본 팝업 대신 디자인에 맞춘 확인 창과 하단 오류 알림
- **송출 화면**: 색 상태 막대(송출 중/대기/문제), 📐 화각 맞추기(전체 화면 + 3분할 안내선), 시작 전 체크리스트
- **로그인**: 아이콘·설명 추가, 손가락으로 누르기 좋은 크기

### 무료 서버로 운영해 보기 (검토)
트래픽이 대부분 직원에게 나가는 사진이라, **무료 서버를 고를 때는 CPU보다 외부 전송량 한도가 중요**하다.
아래 조건은 가입 시점에 따라 바뀌므로 신청 전에 공식 안내를 다시 확인한다.

- [ ] **Oracle Cloud Always Free** 검토 (가장 유력)
  - 기간 제한 없는 무료 VM(ARM), 서울·춘천 리전 있음
  - 외부 전송량 무료 한도가 커서(월 10TB 수준으로 안내됨) 이 시스템에 맞음
  - ⚠ 사용률이 낮은 무료 VM은 회수될 수 있다는 정책이 있음. 퇴근 시간에만 쓰는 이 서비스는 해당될 수 있으니 조건 확인
  - ⚠ 인기 리전은 무료 VM 재고가 없어 생성이 안 될 때가 있음
  - `setup.sh`는 우분투 ARM에서도 그대로 동작해야 함 (Pillow 등 ARM용 패키지 제공) → 설치 후 확인
- [ ] **네이버 클라우드 신규 가입 크레딧** 확인: 이미 승인받은 업체라 회사 승인 절차가 가장 간단
- [ ] AWS / GCP 무료 등급은 비교만: 외부 전송량 한도가 작거나 기간이 정해져 있어 500명 운영에는 맞지 않을 가능성이 큼
- [ ] 무료 서버로 바꾸면 **회사 승인 범위(네이버 클라우드로 승인)를 다시 확인**
- [ ] 무료 서버에서 부하 시험(`loadtest/loadtest.py`)으로 500명 처리 가능 여부와 전송 속도 확인
- [ ] 무료 서버가 회수되거나 멈출 때를 대비해 `cctv.db` 정기 백업 (계정·카메라 설정만 있으면 새 서버에서 바로 복구 가능)

### 이후 고도화 후보

## 알려진 한계
- 송출 페이지는 화면이 꺼지거나 다른 앱으로 넘어가면 멈춘다. 화면 꺼짐 방지와 앱 고정으로 운영한다.
- 서버를 재시작하면 마지막 사진이 사라진다 (다음 업로드 때 바로 복구됨). 접속 중 표시도 0부터 다시 센다.
- 알림음은 관리자 화면을 열어 두었을 때만 울린다. 화면을 닫아도 알림을 받으려면 텔레그램을 켠다.
- 자정을 넘기는 운영 시간(예: 22:00~02:00)은 지원하지 않는다.
